# คำศัพท์ (Glossary)

🏠 [หน้าหลัก](../README.md)

คำศัพท์ที่เจอบ่อยในหลักสูตร ND69 อธิบายแบบสั้นสำหรับมือใหม่ เรียงตามหมวด

## ฮาร์ดแวร์และ Firmware (ND1)

### Edge AI
AI ที่ประมวลผลบนตัวอุปกรณ์เอง ไม่ต้องส่งข้อมูลไป cloud — ตอบสนองเร็ว ใช้เน็ตน้อย ข้อมูลไม่ออกจากเครื่อง

### IoT
Internet of Things — อุปกรณ์ที่ต่อเครือข่ายเพื่อส่งข้อมูลและรับคำสั่ง เช่น sensor ในโรงงาน, smart home

### Firmware
โปรแกรมที่ฝังอยู่ในไมโครคอนโทรลเลอร์ ทำงานทันทีที่จ่ายไฟ

### ESP32-S3
ไมโครคอนโทรลเลอร์ของ Espressif มี 2 core, WiFi, Bluetooth และคำสั่งช่วยเร่ง AI — ชิปหลักของบอร์ดในหลักสูตร

### ESP-IDF
ชุดเครื่องมือทางการของ Espressif (framework + compiler + build system) ใช้ผ่านคำสั่ง `idf.py`

### Flash (firmware)
การเขียนไฟล์ firmware ลงหน่วยความจำของบอร์ด (`idf.py flash`) — คำว่า Flash ยังหมายถึงหน่วยความจำถาวรที่เก็บโปรแกรมด้วย

### SRAM / PSRAM
SRAM = หน่วยความจำในชิป เร็วแต่เล็ก · PSRAM = หน่วยความจำภายนอก ใหญ่แต่ช้ากว่า · ทั้งคู่ข้อมูลหายเมื่อไฟดับ

### NVS
Non-Volatile Storage — พื้นที่เก็บค่าแบบ key-value ใน Flash ข้อมูลอยู่ต่อแม้ถอดปลั๊ก เช่น รหัส WiFi

### FreeRTOS
ระบบปฏิบัติการขนาดเล็กแบบ real-time แบ่งงานเป็นหลาย task ที่สลับกันทำงานตามลำดับความสำคัญ

### Task
หน่วยงานหนึ่งใน FreeRTOS มีสถานะ Running / Ready / Blocked / Suspended

### Mutex
"กุญแจ" ที่ให้ task เดียวใช้ทรัพยากรร่วม (เช่นบัส I2C) ได้ทีละตัว

### Race condition
ปัญหาที่หลาย task / หลาย core แย่งใช้ข้อมูลเดียวกันพร้อมกัน ผลลัพธ์จึงเพี้ยนแบบสุ่ม

### I2C
บัสสื่อสาร 2 เส้นสำหรับต่ออุปกรณ์หลายตัว เช่น touch screen, sensor

### I2S
บัสสำหรับส่งข้อมูลเสียงแบบดิจิทัล ระหว่างชิปกับ audio codec

### PWM
Pulse Width Modulation — ปรับความกว้างพัลส์เพื่อคุมความสว่าง LED หรือความเร็วมอเตอร์

### IMU
Inertial Measurement Unit — sensor วัดความเร่งและการหมุน ใช้รู้ท่าทางหรือการเอียงของอุปกรณ์

### Datasheet
เอกสารสเปกของชิปหรืออุปกรณ์จากผู้ผลิต — ควรให้ AI อ่านก่อนเขียนโค้ดเสมอ

### Board twin
โปรแกรมบอร์ดจำลองบน PC ใช้ฝึก FreeRTOS โดยไม่ต้องมีบอร์ดจริง

### PATH
รายชื่อโฟลเดอร์ที่ terminal ใช้หาคำสั่ง ถ้าคำสั่งไม่อยู่ใน PATH จะได้ error `command not found`

## เว็บแอปที่คุยกับฮาร์ดแวร์ (ND2)

### Telemetry / Command / Event
3 รูปแบบข้อมูลระหว่างแอปกับอุปกรณ์ — telemetry = ค่าที่อุปกรณ์ส่งมา · command = คำสั่งจากแอป · event = อุปกรณ์แจ้งเองเมื่อมีการเปลี่ยนแปลง

### Web Serial
API ของเบราว์เซอร์ Chromium สำหรับคุยกับอุปกรณ์ที่ต่อสาย USB/serial โดยตรง

### Web Bluetooth
API ของเบราว์เซอร์ Chromium สำหรับคุยกับอุปกรณ์ Bluetooth Low Energy (BLE)

### GATT
โครงสร้างข้อมูลของ BLE แบบต้นไม้: service → characteristic → value

### Secure context
หน้าเว็บที่เปิดผ่าน HTTPS หรือ `localhost` — API ที่แตะฮาร์ดแวร์ใช้ได้เฉพาะในหน้าแบบนี้

### Gateway
ตัวกลางที่รวบรวมข้อมูลจากอุปกรณ์หลายตัวก่อนส่งต่อไปยัง server หรือ cloud

### DOM
โครงสร้างของหน้าเว็บที่ JavaScript/TypeScript สร้าง แก้ไข และผูก event ได้

### JSON lines
ส่งข้อมูลเป็น JSON ทีละบรรทัด แต่ละบรรทัดคือ 1 ข้อความ — แยกข้อความง่ายเมื่อข้อมูลไหลต่อเนื่อง

### Fallback
ทางสำรองเมื่อวิธีหลักใช้ไม่ได้ เช่น Bluetooth ปิดอยู่ให้ลอง Serial แทน

### Capability gating
ตรวจก่อนว่าบอร์ดรองรับอะไร (เช่นมี LED ไหม) แล้วเปิดเฉพาะฟีเจอร์ที่รองรับ

## หุ่นยนต์และ Digital Twin (ND3)

### ROS 2
Robot Operating System 2 — framework กลางสำหรับให้โปรแกรมหลายตัวในหุ่นยนต์ส่งข้อความหากัน (ไม่ใช่ระบบปฏิบัติการจริง และไม่ใช่ real-time)

### Middleware
ซอฟต์แวร์ตัวกลางที่จัดการการส่งข้อมูลระหว่างโปรแกรม เช่น ROS 2, robotos

### Node
โปรแกรมหนึ่งตัวในระบบ ROS ทำหน้าที่เดียว เช่น อ่าน sensor หรือคุมมอเตอร์

### Topic
ช่องทางส่งข้อมูลต่อเนื่องแบบ publish/subscribe ใครสนใจก็ subscribe ได้

### Service
การถาม-ตอบระหว่าง node (request → response) ใช้กับงานสั้น ๆ

### Action
งานที่ใช้เวลา มี feedback ระหว่างทาง ยกเลิกได้ และต้องมีผลลัพธ์เสมอ เช่น สั่งหุ่นเดินไปจุดหมาย

### Parameter
ค่าตั้งของ node ที่เปลี่ยนได้ขณะรัน คล้ายแก้ tag table ของ PLC แบบ online

### QoS
Quality of Service — กำหนดว่าข้อความต้องส่งถึงแน่นอนหรือเอาล่าสุดพอ และเก็บย้อนหลังกี่ข้อความ

### TF
Transform — ระบบพิกัดที่บอกว่าชิ้นส่วนแต่ละชิ้นของหุ่นยนต์อยู่ตรงไหนเทียบกับอะไร

### Digital Twin
ภาพจำลองที่มีชีวิตของเครื่องจริง รับ state จากเครื่องจริงและส่งคำสั่งกลับได้ โดยใช้สัญญาข้อมูลเดียวกัน

### OPC UA
มาตรฐานการสื่อสารและ information model ในโรงงาน ใช้กับ PLC / SCADA / MES

### micro-ROS
ROS 2 ฉบับย่อสำหรับไมโครคอนโทรลเลอร์ ให้ MCU เป็นส่วนหนึ่งของระบบ ROS ได้

### Twist / Odometry
Twist = คำสั่งความเร็ว (เดินหน้า + หมุน) · Odometry = ตำแหน่งและทิศที่หุ่นคำนวณจากการเคลื่อนที่ของตัวเอง

### Closed loop
การควบคุมที่ใช้ค่าที่วัดได้ (feedback) มาปรับคำสั่ง ต่างจาก open loop ที่สั่งตามเวลาอย่างเดียว

### State machine
การออกแบบพฤติกรรมเป็นสถานะ (เช่น CRUISE / AVOID / RECOVER) และเงื่อนไขการเปลี่ยนสถานะ

## การสื่อสารและความปลอดภัย

### MQTT
โปรโตคอล publish/subscribe ที่นิยมใน IoT อุปกรณ์ส่งข้อความไปยัง topic ผ่านตัวกลางที่เรียกว่า broker

### TLS
การเข้ารหัสการสื่อสาร (ตัว S ใน HTTPS) ป้องกันการดักฟังและปลอมตัว

### OTA
Over-The-Air update — อัปเดต firmware ผ่านเครือข่าย ควรตรวจลายเซ็นและ rollback ได้ถ้าอัปเดตพัง

### Provisioning
ขั้นตอนลงทะเบียนอุปกรณ์ใหม่เข้าระบบ เช่น ใส่ certificate และค่าเริ่มต้น

## เครื่องมือและการทำงาน

### Git
โปรแกรม version control เก็บประวัติการแก้ไขไฟล์ ย้อนกลับเวอร์ชันได้ — ดู [Git, GitHub และ Markdown](git-github-markdown.md)

### Repository
ที่เก็บโปรเจกต์พร้อมประวัติทั้งหมด (เรียกสั้น ๆ ว่า repo)

### Commit
จุดบันทึกการเปลี่ยนแปลง 1 ครั้งพร้อมข้อความอธิบาย

### Pull Request
คำขอรวมงานจาก branch หนึ่งเข้า branch หลัก ให้ทีมรีวิวก่อน merge

### Markdown
ภาษาเขียนเอกสารแบบข้อความธรรมดาที่ GitHub แสดงผลให้สวย

### AI agent
AI ที่ลงมือทำงานเองได้ เช่น รันคำสั่ง แก้ไฟล์ build และทดสอบ (Claude Code, Copilot, Cursor) ต่างจาก chat ที่ตอบอย่างเดียว
